# Bidirectional TTS (v0.3.0)

Implemented against [the official V3 API](https://docs.volcengine.com/docs/6561/2532486?lang=zh)
and LiveKit Agents 1.6.10. TTS is included starting with v0.3.0;
v0.2.0 and earlier only include STT.

```python
from livekit.plugins import volcengine

engine = volcengine.TTS(
    speaker="VOICE_ID_FROM_CONSOLE",
    # api_key=...; alternatively VOLCENGINE_TTS_API_KEY or VOLCENGINE_API_KEY
    resource_id="seed-tts-2.0",
    sample_rate=24000,
    speech_rate=0,
    loudness_rate=0,
    context_texts=["用自然亲切的语气说话"],  # Optional, compatible 2.0 voices only
)
# AgentSession(tts=engine, ...)
```

Outside AgentSession, supply an aiohttp ClientSession through `http_session`.
The caller closes that session; `engine.aclose()` closes synthesis streams and
pooled WebSockets. Empty input does not open a WebSocket.

`stream()` accepts `push_text()` incrementally; `flush()` or `end_input()` ends
that synthesis. Use a new stream for each reply (SDK 1.6.10 deprecates multiple
segments in one stream). `synthesize(text)` accepts complete text and streams
the resulting audio. Both use the same bidirectional transport.

Only mono signed 16-bit PCM is currently exposed. Supported sample rates are
8000, 16000, 22050, 24000, 32000, 44100 and 48000 Hz. Speech and loudness rates
are integers from -50 to 100. `model` is optional for cloned voices and cannot
be combined with `context_texts`. Cloned voices are not live-qualified here.

## Extensions

`additions={...}` is encoded into the provider's JSON-string additions field;
use it for Markdown filtering, pronunciation hints or optional provider fields.
Named `context_texts` takes precedence over the same additions key.
`extra_request_params={...}` adds unmodeled req_params fields. It cannot override
text, speaker, model, audio_params or additions; use named options instead.
This intentionally differs from the older STT escape hatch: output PCM settings
must remain consistent with LiveKit's AudioEmitter.

Encoded audio formats, voice-management/training APIs and
automatic section_id persistence are outside this version. Unmodeled additions
are serialized and validated as JSON, not claimed as live-qualified features.

## Usage and failures

```python
@engine.on("usage_collected")
def on_usage(usage: volcengine.TTSUsage):
    print(usage.request_id, usage.logid, usage.text_words)
```

The plugin requests provider usage with `X-Control-Require-Usage-Tokens-Return: *`.
Successful SessionFinished usage emits `TTSUsage` including the original usage
object. `text_words` is the provider-reported billing character count, not SDK
input characters or LLM tokens. Missing usage is not zero. Canceled/failed
requests may still be billed without returning final usage; no exact invoice
or cost claim is made. The backend has not added TTS cost estimation.

Connection reuse only follows a clean SessionFinished. Cancellation sends a
best-effort CancelSession and closes/discards the socket. LiveKit owns retries
and input replay; errors after emitted audio do not replay the whole utterance.
`conn_options.timeout` bounds each handshake/send/receive wait; waiting for the
first input token does not acquire a socket. Shutdown control messages have a
one-second best-effort deadline. No custom heartbeat or text replay queue exists.

## Typed controls (2026-09-08 documentation snapshot)

The following optional keyword arguments use the provider's names. `None` omits
an option, preserving upstream defaults; explicit `False` and `0` are sent.
Named values override the same additions field, then the effective additions
are validated. Unknown additions remain JSON extensions. These controls are
plugin APIs; backend YAML has not been expanded in this change.

| Keyword | Wire location / validation |
|---|---|
| `enable_subtitle` | `audio_params`; bool; receive `subtitle` events |
| `disable_markdown_filter`, `disable_emoji_filter` | `additions`; bool; see observed semantics below |
| `max_length_to_filter_parenthesis` | `additions`; nonnegative integer; 0 disables; 0-100 is recommended, not a hard maximum |
| `latex_parser` | `additions`; `v2`, requires effective `disable_markdown_filter=True` |
| `explicit_language` | `additions`; documented language code; may omit other languages or fail when none matches |
| `explicit_dialect` | `additions`; documented dialect code; caller must select a compatible voice |
| `aigc_watermark` | `additions`; bool; provider audible end marker |
| `pitch` | `additions.post_process.pitch`; integer -12 through 12; preserves other post_process fields |
| `section_id` | `additions`; nonempty caller-owned ID; plugin does not generate/persist business history |
| `pronunciation_dict` | `additions`; `{"tone": ["source/target"]}`; at most 5000 rules, unique nonempty sources <=9 characters without whitespace |

Pronunciation rules use the first slash as separator; targets may be text or
provider phonetic notation. The plugin does not reimplement phonetics or SSML.
The supplied documentation labels tone as object but demonstrates a string
array; this implementation follows that array and verifies it against the API.
Matching pronunciation rules can suppress SSML according to the provider; choose
one rather than expecting this plugin to reconcile them. Resource/voice support
is not guessed from voice names or a static voice catalog.

```python
engine = volcengine.TTS(
    speaker="zh_female_vv_uranus_bigtts",
    disable_markdown_filter=True,
    pronunciation_dict={"tone": ["omg/oh my god"]},
    enable_subtitle=True,
)


@engine.on("subtitle")
def on_subtitle(event: volcengine.TTSSubtitle):
    # Raw provider payload preserves text, words and phonemes, including unknown fields.
    # Timestamp values are not converted to browser/Room playback time.
    print(event.request_id, event.payload.get("words"))
```

Subtitles carry the synthesis request/session ID and handshake logid. Foreign
session IDs and non-object payloads fail instead of emitting uncorrelated events.
The event is incremental, not a complete final transcript; canceled synthesis
may already have emitted subtitles. Consumers own display and cancellation.
Event code 364 is confirmed by the official downloadable Python protocol demo.

### Real VV-voice control observations (2026-09-09)

Seven requests completed and returned audio plus subtitle events. This is
service evidence for those examples, not general audible accuracy validation.

| Pair / case | Returned subtitle observation |
|---|---|
| Markdown false / true | `**Hello**` retained / `Hello` without stars; `$29.99` and `20%` retained in both |
| Emoji false / true | Emoji absent / present in subtitle text: opposite to the supplied documentation's description |
| Parenthesis 0 / 20 | `（仅限今天）` retained / removed |
| `omg/oh my god`, language `en` | Subtitle contains `oh my god` |

Do not infer flag semantics solely from the `disable_` prefix or silently invert
values. User listening acceptance on 2026-09-09 passed all ten VV samples:
English prices/symbols, mixed Chinese/English, filter pairs and pronunciation.
Markdown false pronounced the stars; true omitted them. Neither Emoji sample
pronounced the emoji, but the user heard a happier, emoji-consistent "Hello"
with true. This is a subjective observation for one pair, not proof of a
deterministic emotion-control effect. Subtitle retention does not establish
audible symbol pronunciation; the documented flag discrepancy remains noted.
Pitch, dialect, LaTeX, audible watermark and section history have wire/validation
tests but are not live-qualified by these seven requests. No default filter was
enabled. PCM remains fixed; compressed formats, bit rate and container metadata
watermark (`aigc_metadata`) are not exposed as named capabilities.
